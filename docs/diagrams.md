# diagrams

## The design problem (from `docs/brief.md`)

The dotted line is the whole point of this project: the controller has no way to be told something changed in Postgres, only to ask.

```mermaid
flowchart LR
    U[kubectl apply PgDatabase] --> API[kube-apiserver]
    API -->|watch| C[PgDatabase controller]
    C -->|RequeueAfter poll| C
    C -->|SQL: catalog queries,<br/>CREATE ROLE / DATABASE| PG[(Postgres)]
    C -->|write Secret + status| API
    PSQL[psql: DROP DATABASE<br/>ALTER ROLE — drift] --> PG
    C -.no watch available.-x PG
```

## Phase 1 as-built

What actually exists right now: Postgres running in `kind`, and the controller — on the host, not yet deployed in-cluster — connecting to it once at startup. There is no `PgDatabase` reconciliation yet; this diagram will grow a `Reconcile()` loop in Phase 2.

```mermaid
flowchart TB
    subgraph Host["macOS host"]
        Ctrl["controller (make run)<br/>go run ./cmd/main.go"]
    end

    subgraph Kind["kind cluster: pg-lab"]
        API[kube-apiserver]
        Secret["Secret postgres/postgres-superuser<br/>(password only, generated by make setup)"]
        subgraph NS["namespace: postgres"]
            Svc["Service postgres<br/>NodePort 30432 -> 5432"]
            SS["StatefulSet postgres<br/>1 replica, image postgres:16.4"]
            PVC[("PVC data-postgres-0")]
        end
    end

    Ctrl -->|"1. GET secret (client-go)"| API
    API -->|"2. password"| Ctrl
    Ctrl -->|"3. SELECT version()<br/>over localhost:55432<br/>(kind extraPortMappings)"| Svc
    Svc --> SS
    SS --- PVC
    Secret -.read by.-> API
    Ctrl -->|"registers watch (unused this phase)"| API
```

**Reading it:** step 3 is the only Postgres traffic this phase produces — one `SELECT version()` per controller startup, no polling loop yet. The host reaches the cluster's `NodePort` Service through the port mapping baked into `deploy/kind-config.yaml` (container port `30432` → host port `55432`), because the controller runs as a plain host process in this phase, not as a Pod inside the cluster's network.
